# macOS bridge initialization failure (November 2026)

The installed 0.7.0.15 plugin appeared in Stream Deck, and its macOS watcher was running, but the watcher repeatedly timed out enabling Codex Micro. The diagnostic reported `enabled:[true]`, `detected:null`, `nativeEventBus:false`, and `deviceHandlers:0`. A bridge state file existed, but its presence alone did not establish a working bridge. The observed log contained this failure from at least October 21 through November 2. macOS reported version 27.2. The Codex app version could not be read in the sandbox.

The runtime override searched only a fixed set of renderer module names for the native event bus. Upstream [PR #16](https://github.com/dazer1234/codex-stream-deck/pull/16) reports that newer Codex builds expose it in `app-shared-*` and validates that change on Windows. Including `app-shared` in discovery and verification restored initialization on this Mac: the live renderer reported one device handler, successful device-event dispatch, and one each of the HID and joystick handlers. After installing the updated watcher, its log confirmed that it reused the healthy bridge. Individual Stream Deck actions were not exercised in that check.

For a recurrence, inspect `~/Library/Application Support/CodexDeck/watcher.log` and compare the installed watcher with the launcher source. After building and installing an updated watcher using the macOS instructions, check for successful initialization and exercise the configured keys. Avoid restarting Codex during active work; a recovery restart can interrupt sessions. Do not include bridge state files or personal paths in public bug reports.
